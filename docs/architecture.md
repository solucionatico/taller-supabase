# Arquitectura del Proyecto (`taller-supabase`)

## 1. Visión General

El proyecto implementa una aplicación web de gestión de tareas personales con una arquitectura **Serverless / Jamstack** en un único repositorio (**Monorepo**), utilizando servicios administrados gratuitos:

```mermaid
flowchart LR
    subgraph Cliente ["Navegador del Usuario"]
        SPA["Vue 3 + Vite SPA"]
    end

    subgraph Vercel ["Vercel (Hosting Estático)"]
        CDN["Red Global HTTPS / CDN"]
    end

    subgraph Supabase ["Supabase (Backend as a Service)"]
        Auth["Supabase Auth (JWT)"]
        EF["Edge Function: tasks (Deno JS)"]
        DB[("PostgreSQL + RLS (public.tasks)")]
    end

    CDN -->|Sirve HTML/CSS/JS| SPA
    SPA -->|1. Registro / Login / Sesión| Auth
    SPA -->|2. Petición CRUD + Bearer JWT| EF
    EF -->|3. Consulta con JWT del usuario| DB
    DB -->|4. Política RLS: auth.uid() = user_id| EF
```

## 2. Componentes de la Arquitectura

### 2.1. Frontend (`apps/web/`)
- **Tecnologías**: Vue 3 (Composition API con `<script setup>`), Vue Router 4, Vite, HTML5, CSS3 moderno y `@supabase/supabase-js`.
- **Lenguaje**: JavaScript puro (ES Modules, `.js` y `.vue`).
- **Responsabilidades**:
  - Gestionar el registro, inicio de sesión, cierre de sesión y persistencia de sesión directamente contra **Supabase Auth**.
  - Proteger las rutas privadas mediante guardias de navegación (`router.beforeEach`).
  - Mostrar la información básica del usuario autenticado (nombre completo desde `user_metadata.full_name` y correo electrónico).
  - Invocar la Edge Function `tasks` mediante `supabase.functions.invoke('tasks', { body })` para todas las operaciones CRUD de tareas (`list`, `create`, `update`, `delete`).
- **Hospedaje**: Desplegado como sitio estático en **Vercel** mediante Vercel CLI (`npm run deploy:web`), configurado a través de `vercel.json` en la raíz.

### 2.2. Backend / API (`supabase/functions/tasks/index.js`)
- **Tecnologías**: Supabase Edge Functions sobre **Deno Runtime**, escrito en **JavaScript puro (`index.js`)**.
- **Autenticación y Seguridad**:
  - Configurado en `supabase/config.toml` con `verify_jwt = true` y `entrypoint = "./functions/tasks/index.js"`.
  - Extrae el encabezado `Authorization: Bearer <jwt>` enviado por el cliente.
  - Inicializa un cliente `@supabase/supabase-js` utilizando `SUPABASE_URL` y la clave publicable/anónima del entorno (`SUPABASE_ANON_KEY` / `SUPABASE_PUBLISHABLE_KEY`), propagando el encabezado `Authorization` del usuario.
  - Verifica explícitamente la identidad del usuario con `supabase.auth.getUser()` antes de procesar cualquier acción.
  - **No utiliza `SUPABASE_SERVICE_ROLE_KEY`** para operaciones del usuario, garantizando que PostgreSQL aplique Row Level Security (RLS) en cada consulta.
- **Contrato de la API (`POST /functions/v1/tasks`)**:
  - Basado en un campo `action` en el cuerpo JSON:
    - ` { "action": "list" } ` → Lista las tareas del usuario autenticado ordenadas por fecha de creación descendente.
    - ` { "action": "create", "title": "...", "description": "..." } ` → Crea una nueva tarea asociada automáticamente a `auth.uid()`.
    - ` { "action": "update", "id": 1, "completed": true, "title": "...", "description": "..." } ` → Actualiza el estado o contenido de una tarea perteneciente al usuario.
    - ` { "action": "delete", "id": 1 } ` → Elimina una tarea perteneciente al usuario.
  - Soporta preflight `OPTIONS` y encabezados **CORS** compatibles tanto con `localhost` como con dominios `.vercel.app`.

### 2.3. Base de Datos (`supabase/migrations/`)
- **Motor**: PostgreSQL administrado por Supabase.
- **Tabla principal**: `public.tasks`
  - `id`: `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`
  - `title`: `TEXT NOT NULL` (con validación de longitud no vacía)
  - `description`: `TEXT` (opcional)
  - `completed`: `BOOLEAN NOT NULL DEFAULT FALSE`
  - `user_id`: `UUID NOT NULL DEFAULT auth.uid() REFERENCES auth.users(id) ON DELETE CASCADE`
  - `created_at`: `TIMESTAMPTZ NOT NULL DEFAULT NOW()`
- **Índices y Seguridad**:
  - Índice `idx_tasks_user_id` sobre `public.tasks(user_id)` y `idx_tasks_created_at` para optimizar consultas por usuario.
  - **Row Level Security (RLS)** habilitado con cuatro políticas estrictas (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) que comparan `auth.uid() = user_id`.

### 2.4. Automatización y Scripts (`scripts/`)
Escritos en JavaScript con ES Modules (`"type": "module"` en `package.json`), ejecutables en Windows, Linux y macOS sin Bash ni PowerShell:
- `scripts/check-environment.js`: Verifica versión de Node.js (>= 22), disponibilidad de `npm`, instalación de `node_modules`, binarios locales de `supabase` y `vercel`, y archivos esenciales del proyecto.
- `scripts/setup.js`: Asistente interactivo paso a paso para guiar al estudiante en la creación/configuración de `.env`, login y vinculación con Supabase CLI (`supabase link`) y Vercel CLI (`vercel link`).
- `scripts/deploy-functions.js`: Recorre `supabase/functions/`, ignora carpetas que comienzan con `_` (como `_shared`) y despliega cada función mediante el binario local de Supabase CLI.
- `scripts/deploy.js`: Orquesta el despliegue completo en 4 etapas secuenciales: verificación de entorno, migraciones SQL (`db push`), despliegue de Edge Functions y despliegue del frontend a producción en Vercel.
